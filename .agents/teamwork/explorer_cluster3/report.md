## 1. Резюме для владельца проекта (Executive Summary)

В ходе детального исследования кодовой базы лаунчера по трем назначенным направлениям (**Направление 4: Стейт фронтенда и утечки**, **Направление 5: Доступность (a11y) и навигация**, **Направление 6: Интернационализация (i18n)**) выявлен ряд существенных архитектурных дефектов, расхождений с ранее заявленными статусами (в `AUDIT.md` и `docs/DECISIONS.md`), а также рисков утечек ресурсов и деградации производительности:

1. **Ре-рендер всего дерева UI при работающей игре (опровержение решения D8 / D29):**  
   Несмотря на отметку «УСТРАНЕНО» в бэклоге D8, корневой компонент `Shell.tsx` (строка 58) вызывает хук `useInstances()` без селектора и без `useShallow`. В результате при запуске игры таймер сброса буфера логов (каждые 200 мс) и события прогресса загрузки вызывают полный ре-рендер `Shell` и всех дочерних страниц, нивелируя оптимизацию `memo(InstanceRow)`.
2. **Потеря «хвоста» логов при краше игры и подмена логов в просмотрщике:**  
   При событии `Exited` сброс логов в `instances.ts` происходит синхронно, однако Tauri IPC доставляет строки логов асинхронно по отдельному каналу `game_log_line`. Хвост лога с критическим стек-трейсом краша поступает в буфер уже после вызова `crashAnalyze`, в результате чего диагностика краша и модалка отчёта о сбое не содержат финальных строк. Кроме того, встроенный `LogViewerModal` при пустом буфере сессии отображает `launcher.log` (собственный лог лаунчера), вводя пользователя в заблуждение, будто это лог Minecraft.
3. **Критический разрыв паритета между Главной (`HomePage`) и страницей «Инстансы»:**  
   Диалог честного удаления инстанса («в корзину / навсегда», решение D7/D28) и пункты кебаб-меню (бэкап zip, экспорт .mrpack, управление иконками) были добавлены только в `InstancesPage.tsx`. На главной странице `HomePage.tsx` строка инстанса по-прежнему использует блокирующий браузерный `window.confirm()` со статическим `wipe: false`, а пункты бэкапа, экспорта и смены иконки отсутствуют вовсе.
4. **Невыполненные требования доступности и модальных окон (D21):**  
   Ни одно из 7 модальных окон лаунчера не имеет реализации захвата фокуса (focus trap) и возврата фокуса на вызвавший элемент при закрытии. Диалог создания инстанса (`CreateInstanceDialog.tsx`) полностью игнорирует клавишу `Escape` и клики по оверлею. Переключатели `Toggle` в настройках не имеют `aria-label`/`aria-labelledby`, делая их невидимыми для скринридеров.
5. **Дефекты локализации, отсутствие ключа в словаре и сломанные E2E-тесты при `en` по умолчанию:**  
   Словарь украинского языка `uk.json` содержит 225 ключей вместо 226 (пропущен обязательный ключ `accounts.title`, что приводит к выпадению на английский язык). В украинской локализации присутствуют грубые орфографические ошибки (русское слово `"можно"` вместо `"можна"`, родительный падеж `"Тем"` вместо `"Теми"`). При этом ВСЕ тестовые скринридер/E2E-скрипты в папке `scripts/` содержат жестко захардкоженные русскоязычные селекторы, из-за чего при установке лаунчера на чистую систему (где по D30 язык по умолчанию `en`) все автотесты гарантированно падают.

## 3. Детальные находки по Направлению 4: Стейт фронтенда и утечки памяти

### Находка 4.1. Разрегулированность буфера логов и потеря строк перед crash-анализом
- **Локализация:** `src/state/instances.ts:46-84`, `src/state/instances.ts:147-175`, `src-tauri/src/instances/run.rs:694-710`
- **Приоритет:** **P1**
- **Технические наблюдения:**
  1. В `src/state/instances.ts:46-48`:
     ```ts
     const LOG_FLUSH_MS = 200;
     const LOG_BUFFER_MAX = 500;
     const LOG_KEEP = 300;
     ```
     В функции `queueLogLine` буфер накапливает до `LOG_BUFFER_MAX` (500) строк. Однако в `flushLogs` (строка 80) выполняется срез:
     ```ts
     logs[id] = merged.length > LOG_KEEP ? merged.slice(merged.length - LOG_KEEP) : merged;
     ```
     Если игра выдала всплеск из 500 строк за 200 мс, то при первом же вызове `flushLogs` 200 строк гарантированно отбрасываются.
  2. В `src/state/instances.ts:147-175`:
     При получении события `launch_state` с `phase === "exited"` вызывается синхронный `flushLogs()`, после чего немедленно вызывается `api.crashAnalyze(logText)`.
     Однако в бэкенде (`src-tauri/src/instances/run.rs:694-701`) при обнаружении завершения дочернего процесса (`child.try_wait()`) событие `LaunchState::Exited` отправляется в общую шину немедленно. При этом параллельные потоки вычитывания stdout/stderr (`run.rs:669-677`) и IPC-мост (`commands/mod.rs:922-923`) передают `game_log_line` и `launch_state` независимо.
     Если последние строки лога (содержащие сам стек-трейс краша JVM или мода) доставляются в WebView хотя бы на 1 микросекунду позже события `exited`, они попадают в `logBuffer` через `queueLogLine` и откладываются на 200 мс. В `crashAnalyze` уходит устаревший срез логов, в котором краш-сигнатуры отсутствуют, а в модалке `CrashReportModal` поле `logTail` фиксирует состояние до прихода хвоста.
- **Риск:** Ложноотрицательный анализ крашей, потеря последних строк вывода игры при аварийном завершении.

### Находка 4.2. Семантический дефект LogViewerModal: подмена игрового лога системным

  ```ts
  if (!instanceLogs || instanceLogs.length === 0) {
  ```

- **Риск:** Введение пользователя и саппорта в заблуждение при диагностике неполадок.

### Находка 4.3. Нарушение подписки Zustand в Shell.tsx: каскадный ре-рендер всего приложения
- **Локализация:** `src/ui/layout/Shell.tsx:58`, `src/App.tsx:11`
- **Приоритет:** **P1**
- **Технические наблюдения:**
  В `src/ui/layout/Shell.tsx:58`:
  ```tsx
  const { load, subscribeEvents, list, crashReport, clearCrashReport } = useInstances();
  ```
  Хук `useInstances` вызван без селектора. В Zustand вызов без селектора подписывает компонент на абсолютно любые изменения в объекте стора.
  Поскольку `useInstances` хранит `logs: Record<string, string[]>`, каждый вызов `flushLogs()` (каждые 200 мс во время работы игры), а также каждое событие `dl_progress` вызывают перерендер компонента `Shell`.
  Так как страницы в `Shell.tsx` (строки 344–350: `HomePage`, `InstancesPage`, `ModsPage`, `SettingsPage`) не обёрнуты в `memo()`, происходит регулярный каскадный ре-рендер всей активной страницы, виртуального DOM и всех дочерних элементов 5 раз в секунду.
- **Предложение:** Заменить на вызов с селектором и `useShallow`:
  ```tsx
  const { load, subscribeEvents, list, crashReport, clearCrashReport } = useInstances(
    useShallow((s) => ({
      load: s.load,
      subscribeEvents: s.subscribeEvents,
      list: s.list,
      crashReport: s.crashReport,
      clearCrashReport: s.clearCrashReport,
    }))
  );
  ```

### Находка 4.4. Необратимая утечка подписки на события ядра Tauri (отсутствие unlisten)
- **Локализация:** `src/state/instances.ts:129-133`, `src/api/client.ts:132-140`, `src/ui/layout/Shell.tsx:117-122`
- **Приоритет:** **P2**
- **Технические наблюдения:**
  1. В `src/api/client.ts:139` функция `onCoreEvent` возвращает `Promise<UnlistenFn>`.
  2. В `src/state/instances.ts:129-133` метод `subscribeEvents`:
     ```ts
     subscribeEvents: async () => {
       if (isSubscribed) return;
       isSubscribed = true;
       await onCoreEvent((event) => { ... });
     }
     ```
     Функция отписки нигде не сохраняется и не возвращается.
  3. В `src/ui/layout/Shell.tsx:117-122`:
     `useEffect` вызывает `void subscribeEvents();` и не возвращает функцию очистки (cleanup).
     При размонтировании `Shell` (например, при выходе в онбординг или в тестах) 4 слушателя Tauri (`dl_progress`, `launch_state`, `game_log_line`, `account_refresh_failed`) остаются зарегистрированными в WebView навсегда, удерживая замыкания на стор.

### Находка 4.5. Утечка таймеров setTimeout при размонтировании модальных окон
- **Локализация:** `src/ui/components/LogViewerModal.tsx:45`, `src/ui/components/CrashReportModal.tsx:28`
- **Приоритет:** **P3**
- **Технические наблюдения:**

## 5. Детальные находки по Направлению 5: Доступность (a11y) и навигация

### Находка 5.1. Полное отсутствие Focus Trap и восстановления фокуса во всех модальных окнах
- **Локализация:** Все модальные компоненты в `src/ui/components/` (`AccountsModal.tsx`, `CrashReportModal.tsx`, `CreateInstanceDialog.tsx`, `InstanceSettingsModal.tsx`, `LogViewerModal.tsx`, `RenameInstanceModal.tsx`), а также диалог удаления в `InstancesPage.tsx:198-254`.
- **Приоритет:** **P2**
- **Технические наблюдения:**
  1. **Focus Trap:** Ни в одном диалоге нет удержания фокуса. При нажатии клавиши `Tab` фокус беспрепятственно покидает окно диалога и перемещается по фоновым элементам страницы (поисковая строка титлбара, кнопки навигации, скрытые кнопки контента), позволяя взаимодействовать со скрытым интерфейсом при открытом модальном окне.
  2. **Восстановление фокуса (Focus Restoration):** При открытии модального окна ссылка на `document.activeElement` не сохраняется, а при закрытии фокус сбрасывается в `document.body` вместо возврата на кнопку вызова (например, кебаб-меню или кнопку «Создать инстанс»), что нарушает WCAG 2.1 Success Criterion 2.4.3 (Focus Order).

### Находка 5.2. CreateInstanceDialog не реагирует на Escape и клик по оверлею
- **Локализация:** `src/ui/components/CreateInstanceDialog.tsx:75-164`
- **Приоритет:** **P2**
- **Технические наблюдения:**
  В компоненте отсутствует обработчик события `keydown` (Escape) и отсутствует обработчик `onClick` на фоновом оверлее (`bg-black/60`). Закрыть окно создания инстанса с клавиатуры невозможно (за исключением навигации табом на иконку крестика `X`). Это прямое нарушение WCAG 2.1 (2.1.1 Keyboard).

### Находка 5.3. Переключатели Toggle в SettingsPage не имеют доступного имени
- **Локализация:** `src/ui/pages/SettingsPage.tsx:379-394`, `src/ui/pages/SettingsPage.tsx:220-228`
- **Приоритет:** **P2**
- **Технические наблюдения:**
  Компонент `Toggle`:
  ```tsx
  function Toggle({ checked, onChange }: { checked: boolean; onChange: (v: boolean) => void }) {
    return (
      <button
        role="switch"
        aria-checked={checked}
        onClick={() => onChange(!checked)}
        className={`h-6 w-11 rounded-full transition-colors ...`}
      >
        <span className={`block h-5 w-5 rounded-full ...`} />
      </button>
    );
  }
  ```
  Элемент `<button role="switch">` не имеет ни атрибута `aria-label`, ни `aria-labelledby`, ни текстовых потомков. Скринридер объявляет его как "switch, checked/unchecked" без названия настройки (снапшоты, старые версии). Это прямо подтверждает ранее открытый пункт бэклога D21 (`тогглы без aria-label`).

### Находка 5.4. Хрупкий обработчик Escape в диалоге удаления инстанса
- **Локализация:** `src/ui/pages/InstancesPage.tsx:199-204`
- **Приоритет:** **P3**
- **Технические наблюдения:**
  ```tsx
  <div
    className="fixed inset-0 z-50 grid place-items-center bg-black/50 p-4"
    onClick={() => setDeleteInst(null)}
  ```

## 6. Детальные находки по Направлению 6: Качество, семантика и полнота i18n

### Находка 6.1. Отсутствие ключа `accounts.title` в словаре `uk.json`
- **Локализация:** `src/i18n/uk.json:120-125`, `src/i18n/ru.json:121`, `src/i18n/en.json:121`
- **Приоритет:** **P2**
- **Технические наблюдения:**
  В файле `uk.json` отсутствует перевод ключа `"accounts.title"`.
  В `en.json`: `"accounts.title": "Accounts Management"`.
  В `ru.json`: `"accounts.title": "Управление аккаунтами"`.
  При включенном украинском языке модальное окно управления профилями (`AccountsModal.tsx:109`) отображает заголовок на английском языке (`"Accounts Management"`), благодаря цепочке fallback `dicts[current][key] ?? dicts.en[key]`.
  Это прямо опровергает утверждение в `docs/DECISIONS.md` (пункт D30.1) о наличии ровно 226 ключей и полном паритете во всех трех языках.

### Находка 6.2. Орфографические и грамматические ошибки в украинской локализации
- **Локализация:** `src/i18n/uk.json` (строки 147, 211, 224)
- **Приоритет:** **P2**
- **Технические наблюдения:**
  1. `uk.json:224`: `"instances.delete.trash": "Видалити в кошик (можно відновити)"`. Использовано русское слово `"можно"`. В украинском языке правильная форма — `"можна"`.
  2. `uk.json:147`: `"themes.title": "Тем"`. Слово переведено в родительном падеже множественного числа («кого/чого? тем») вместо именительного падежа `"Теми"`.
  3. `uk.json:211`: `"instances.export.done": "Експорт готово: {path}"`. Нарушено согласование рода (существительное мужского рода «Експорт» и краткое прилагательное/наречие среднего рода «готово»). Корректно: `"Експорт готовий: {path}"`.
  4. `uk.json:17`: `"mods.by": "автор {author}"`. В украинском контексте каталога модов требуется `"від {author}"` или `"автор: {author}"`.

### Находка 6.3. Отсутствие поддержки грамматического плюрализма (множественного числа)
- **Локализация:** `src/ui/components/LogViewerModal.tsx:80`, `src/i18n/ru.json:63`, `src/i18n/uk.json:63`, `src/i18n/ru.json:18`, `src/i18n/uk.json:18`
- **Приоритет:** **P2**
- **Технические наблюдения:**
  Движок `src/i18n/index.ts` не поддерживает pluralization rules (1, 2–4, 5+).
  В результате:
  1. В просмотрщике логов (`LogViewerModal.tsx:80`):
     `{displayLogs.length} {t("instances.logs.lines")}`
     В `ru.json` значение `"строк"`, в `uk.json` — `"рядків"`.
     При 1 строке пользователь видит: `"1 строк"` (вместо `"1 строка"` / `"1 рядок"`).
     При 2, 3, 4 строках: `"2 строк"` (вместо `"2 строки"` / `"2 рядки"`).
  2. В счетчике скачиваний мода (`mods.downloads`):
     В `ru.json`: `"{n} загрузок"`, в `uk.json`: `"{n} завантажень"`.
     При `n = 1` отображается `"1 загрузок"` (вместо `"1 загрузка"` / `"1 завантаження"`).

### Находка 6.4. Жестко захардкоженная локаль `"ru"` при форматировании дат и чисел
- **Локализация:** `src/ui/pages/HomePage.tsx:155`, `src/ui/pages/ModsPage.tsx:464`
- **Приоритет:** **P2**
- **Технические наблюдения:**
  1. В `HomePage.tsx:155`:
     ```tsx
     new Date(hero.lastPlayed * 1000).toLocaleString("ru", {
       day: "numeric",
       month: "short",
       hour: "2-digit",
       minute: "2-digit",
     })
     ```
     Дата последнего запуска инстанса жестко форматируется на русском языке (например, `"27 сент., 19:30"`), даже если в настройках выбран английский (`"Sep 27, 7:30 PM"`) или украинский (`"27 вер., 19:30"`).
  2. В `ModsPage.tsx:464`:
     ```tsx
     h.downloads.toLocaleString("ru")
     ```
     Количество скачиваний форматируется с русской локалью независимо от выбранного языка интерфейса.

### Находка 6.5. Двуязычные ошибки при fallback подсказок ядра (hint)
- **Локализация:** `src-tauri/src/errors.rs:98-109`, `src/i18n/index.ts:31-36`
- **Приоритет:** **P2**
- **Технические наблюдения:**
  Функция `errorText` в `index.ts`:
  ```ts
  const localized = entry ? (entry[current as keyof ErrorEntry] ?? entry.en ?? entry.ru) : undefined;
  const base = localized ?? e.message;
  return e.hint ? `${base}. ${e.hint}` : base;
  ```
  В ядре Rust (`errors.rs:98-108`) подсказки `hint()` жестко закодированы на русском языке (например: *"Проверьте подключение к интернету; при необходимости настройте прокси в настройках."*).
  Когда пользователь использует английский интерфейс, `base` локализуется на английский, после чего к нему конкатенируется русская подсказка:
  `"Network problem. Check your connection or proxy in settings.. Проверьте подключение к интернету; при необходимости настройте прокси в настройках."`
  Помимо смыслового смешения языков в интерфейсе, формируется двойная точка `.. `, так как строка из словаря уже заканчивается точкой.

### Находка 6.6. Мертвые дублирующие ключи `error.*` в словарях локализации
- **Локализация:** `src/i18n/en.json:178-191`, `src/i18n/ru.json:178-191`, `src/i18n/uk.json:177-190`, `src/i18n/errors.json`
- **Приоритет:** **P3**
- **Технические наблюдения:**
  В файлах `{en,ru,uk}.json` объявлены 14 ключей вида `error.<code_name>`. Однако ни один компонент или модуль в проекте не вызывает `t("error.*")`. Обработка кодов ошибок ядра централизованно осуществляется через `src/i18n/errors.json`. При этом тексты в `errors.json` и `error.*` рассинхронизированы (например, `"File system error."` в `errors.json` против `"File error"` в `en.json`).

### Находка 6.7. Ограничение одинарной замены в функции `t()`
- **Локализация:** `src/i18n/index.ts:23-25`
- **Приоритет:** **P3**
- **Технические наблюдения:**
  ```ts
  for (const [k, v] of Object.entries(params)) {
    text = text.replace(`{${k}}`, String(v));
  }
  ```
  Метод `String.prototype.replace(string, ...)` в JavaScript заменяет только **первое** вхождение подстроки. Если строка перевода содержит плейсхолдер повторно, все последующие вхождения останутся в сыром виде `{k}`. Следует использовать `replaceAll` или глобальное регулярное выражение.
