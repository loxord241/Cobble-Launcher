## 3. Детальные результаты выборочной проверки цитат (Evidence Spot-Check)

Рецензентом была проведена независимая проверка 10 ключевых утверждений аудита по исходному коду:

1. **A1 — Path Traversal в `instance_delete` без `valid_id` (`instances/mod.rs:291-314`, `commands/mod.rs:133-136`):**
   - *Фактический код:* В `instances/mod.rs:291` функция `pub fn delete(paths: &crate::paths::Paths, id: &str, wipe: bool)` сразу вызывает `let dir = instance_dir(paths, id);` без вызова `valid_id(id)`. При передаче относительного пути `id = "..\\backups"` и `wipe: true` ядро вызывает `std::fs::remove_dir_all(long_path(&dir))`, стирая каталог бэкапов.
   - *Вердикт проверки:* **Подтверждено на 100%**. Уязвимость критическая (P0).

2. **A2 — Command Injection в `recycle_dir` через PowerShell (`instances/mod.rs:320-335`):**
   - *Фактический код:* В строке 320 строка скрипта интерполируется как:
     `format!("Add-Type -AssemblyName Microsoft.VisualBasic; [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteDirectory('{}', 'OnlyErrorDialogs', 'SendToRecycleBin')", dir.display());`
     Одинарные кавычки не экранируются. Имя инстанса с апострофом (например, `Steve's; Start-Process calc; #`) приводит к выходу из строкового литерала PowerShell и выполнению произвольного скрипта.
   - *Вердикт проверки:* **Подтверждено на 100%**. Уязвимость критическая (P0 RCE).

3. **A5 — Опровержение D15: Утечка `TcpListener` и потока Tokio при таймауте OAuth (`commands/mod.rs:602-619`, `auth/msa.rs:322-362`):**
   - *Фактический код:* В `commands/mod.rs:613` вызов `wait_auth_code(listener)` обёрнут в `tokio::time::timeout(Duration::from_secs(300), ...)`. В `auth/msa.rs:325` слушатель перемещается в `tokio::task::spawn_blocking(move || { for stream in listener.incoming() { ... } })`. При таймауте задача Tokio `spawn_blocking` НЕ отменяется, а сокет остаётся в блокирующем вызове `accept()`.
   - *Оценка честности аудита:* В `AUDIT.md:220` ранее было ложно заявлено: *«УСТРАНЕНО 2026-09-27: shutdown OAuth-listener по отмене»*. Аудиторы проявили высочайшую честность и профессионализм, опровергнув это утверждение.
   - *Вердикт проверки:* **Подтверждено на 100%**.

4. **A6 — Отсутствие `#[serde(rename_all = "camelCase")]` на `JavaInstall` (`java/detect.rs:9-17`, `InstanceSettingsModal.tsx:165-166`):**
   - *Фактический код:* В `java/detect.rs:9` объявлено:
     `#[derive(Debug, Clone, Serialize, Deserialize)] pub struct JavaInstall { pub java_exe: PathBuf, pub major: u32, pub arch_bits: u32, ... }`.
     Атрибут `rename_all` отсутствует, поля отдаются в JSON как `java_exe` и `arch_bits`. Во фронтенде `InstanceSettingsModal.tsx:165` обращается к `j.javaExe` и `j.archBits`, получая `undefined`.
   - *Вердикт проверки:* **Подтверждено на 100%**. Выпадающий список Java в UI полностью сломан.

5. **A4 — Ложный отказ `ZipSlip` на длинных путях (`util/zip.rs:81-86`, `util/fs.rs:20-27`):**
   - *Фактический код:* `dest_long` формируется через `long_path(dest)`. Если длина `dest` меньше 240 символов, префикс `\\?\` не добавляется. Если файл внутри архива имеет длинный путь `rel`, путь `dest.join(&rel)` превышает 240 символов и получает префикс `\\?\`. Проверка `target.starts_with(&dest_long)` в строке 84 возвращает `false`, вызывая `LauncherError::ZipSlip`.
   - *Вердикт проверки:* **Подтверждено на 100%**.

6. **A8 — Каскадный ре-рендер всего UI 5 раз в секунду (`Shell.tsx:58`, `state/instances.ts:46-80`):**
   - *Фактический код:* В `Shell.tsx:58` вызвано `const { ... } = useInstances()`. В `state/instances.ts:46` установлен `LOG_FLUSH_MS = 200`. При запущенной игре `flushLogs` каждые 200 мс вызывает `useInstances.setState`, меняя ссылку на объект стора и заставляя перерисовываться весь `Shell` и всё дочернее дерево.
   - *Вердикт проверки:* **Подтверждено на 100%**.

7. **A10 — Регресс удаления на Главной странице (`HomePage.tsx:110-128`, `InstancesPage.tsx:225-245`):**
   - *Фактический код:* На `HomePage.tsx:121` остался `window.confirm` с фиксированным вызовом `remove(inst.id, false)` (`wipe: false`), тогда как на `InstancesPage.tsx:225` реализован модальный диалог с выбором «в корзину / навсегда». В кебаб-меню на Главной отсутствуют пункты бэкапа и экспорта.
   - *Вердикт проверки:* **Подтверждено на 100%**.

8. **A36 — Нарушение паритета словарей: пропуск ключа в `uk.json` (`src/i18n/uk.json:120`, `docs/DECISIONS.md:337`):**
   - *Фактический код:* В `ru.json:121` и `en.json:121` есть ключ `"accounts.title"`. В `uk.json` ключ отсутствует (ровно 225 ключей вместо заявленных 226 в D30).
   - *Вердикт проверки:* **Подтверждено на 100%**.

9. **A13 — Юридическая коллизия лицензии (`docs/README.md:69-70`, `LICENSE:1-22`, `Cargo.toml:6`):**
   - *Фактический код:* В `LICENSE` указана лицензия MIT. В `Cargo.toml:6` указано `license = "MIT"`. Однако в `docs/README.md:70` написано: `GPL-3.0 (как у Prism Launcher)`.
   - *Вердикт проверки:* **Подтверждено на 100%**.

10. **A18 — Ложная запись отмененного мода в манифест (`src-tauri/src/modrinth/install.rs:183-209`):**
    - *Фактический код:* В строке 184 проверяется только `if st.failed > 0`. Условие `st.cancelled > 0` не проверяется, и код переходит к добавлению недокачанного мода в `content-manifest.json`.
    - *Вердикт проверки:* **Подтверждено на 100%**.

## 5. Анализ рисков и состязательная оценка (Adversarial Stress-Test)

В роли Adversarial Critic были проанализированы предположения аудита и устойчивость лаунчера к внешним воздействиям:

1. **Анализ критичности уязвимостей:**
   - Выводы аудита о критичности находок A1 (Path Traversal) и A2 (PowerShell Injection) полностью обоснованы. Возможность передачи `id = "..\\backups"` с флагом `wipe: true` через IPC позволяет любому скомпрометированному скрипту в WebView стереть данные за пределами папки инстансов.
   - Находка A3 (RCE через JVM-флаги) подтверждена: передача флагов `-XX:OnError="cmd.exe /c ..."` в конфигурацию инстанса является классическим вектором побега из песочницы при наличии произвольного ввода параметров запуска.
2. **Анализ стабильности тестов:**
   - Предупреждение аудита A42 о флапающих тестах со `sleep` в `download_engine.rs` подтвердилось при запуске: тесты чувствительны к загрузке CPU (прогон занял ~16 секунд из-за последовательных таймингов 400–500 мс). Рекомендация аудита перейти на `tokio::time::pause()` обоснована.
3. **Оценка отсутствия фасадных реализаций:**
   - В ходе проверки не обнаружено признаков того, что тесты проверяют фасадные заглушки без реальной логики (за исключением уже отмеченных в A44 тестов сериализации фикстур).
