# ЗАДАНИЕ: 10 UI-концептов лаунчера Minecraft — обзорная волна дизайна (v2)

Ты — арт-директор уровня Awwwards с руками в вёрстке. Задача — спроектировать и сверстать
**10 самостоятельных вариантов интерфейса** десктопного лаунчера Minecraft и обосновать
каждый данными, чтобы владелец выбрал направление для реального приложения (Tauri 2 +
React + TS + Tailwind; полная спека — `AGENT_PROMPT.md`, читать её не обязательно).

Это дизайн-разведка: **код ядра не трогать**. Результат — статические HTML + скриншоты +
документированные дизайн-системы.

Режим продукта — **Operate** (человек выполняет задачу: запустить игру, поставить мод).
Сканируемость, консистентность и предсказуемость важнее самовыражения; бренд живёт
в точных деталях. Пять «свободных» вариантов могут смещаться к Experience, но не ломая
Operate-суть. Слабое, осторожное, «безопасное» решение = провал: каждый вариант должен
иметь собственную позицию и быть доведённым до конца — никаких полумер и усреднений
между мирами.

## 1. Что сдаём

Каталог `ui-explorations/` в корне проекта:

- `variant-01-<slug>.html` … `variant-10-<slug>.html` — полностью автономные: один файл,
  встроенный CSS, без сборки; JS — только для мелочей (переключение табов в макете).
- `design-systems/<slug>/MASTER.md` — документ дизайн-системы варианта: паттерн, стиль,
  палитра, типографика, эффекты, антипаттерны (генерируется инструментом, см. раздел 2).
- `index.html` — галерея: 10 карточек (имя концепта, вотмард, скриншот, 2–3 фразы идеи,
  ссылки на файл и на его MASTER.md).
- `COMPARISON.md` — сравнительная таблица + **твоя рекомендация top-3** с обоснованием
  с позиций Operate-режима (сканируемость, плотность, консистентность), не только вкуса.

## 2. Инструмент обоснования (обязателен)

На машине установлен локальный поисковик дизайн-знаний (Python 3.14 есть). Для КАЖДОГО
варианта сначала получи дизайн-систему и сохрани её:

```bash
python "C:/Users/Admin/.zcode/skills/ui-ux-pro-max/scripts/search.py" \
  "<запрос по концепту>" --design-system \
  --variance <1-10> --motion <1-10> --density <1-10> \
  -p "<Имя варианта>" --persist --output-dir "ui-explorations"
```

- Диски настраивают характер: `--variance` 1–3 = сдержанный центр (для минимализма),
  7–10 = смелый/асимметричный (брутализм, bento); `--motion` 1–3 = микровзаимодействия,
  7+ = сложная хореография; `--density` 1–3 = воздушно, 7–10 = плотно как в Steam.
- Запрос — 2–5 слов по сути концепта («dark launcher gaming minimal», «retro y2k desktop»).
- Затем точечные запросы по нужде: `--domain style|color|typography|ux|icons|gsap`
  (пример: `"dark ui entertainment" --domain color`). Пустой результат → один retry
  с более узкой фразой → если снова пусто, скажи об этом в MASTER.md и используй
  fallback-дефолты, не выдавая их за данные базы.
- MASTER.md каждого варианта — источник токенов для его HTML: палитра и шрифты в макете
  обязаны совпадать с документом. Произвольные hex вне `:root` запрещены.

Общее: воздух, никакого декора ради декора, один акцентный цвет, сканируемость — на первом
месте. Рекомендованные диски указаны — можешь скорректировать на ±2 по смыслу запроса.

1. **«Сланец» (slate)** — тёмный графит #16181c, монохром + холодный голубой акцент;

   motion 2, density 8.
2. **«Бумага» (paper)** — светлая: тёплый белый #faf9f7, чернильный текст, заголовки 28+,
   мягкие тени вместо границ, акцент киноварь. Диски: variance 2, motion 2, density 3.
3. **«Пульт» (console)** — инженерный: сетка 8px, моноширинные версии/ОЗУ/статусы,

   Диски: variance 3, motion 5, density 6.

## 5. Пять вариантов «на твой вкус» (требования)

5 разных миров — не перекраска минимализма и не вариация CurseForge. Каждому: имя концепта
(русское + slug), название продукта для вотмарда («Кремний», «Кузня», «Vault» — или своё),
3–4 фразы идеи в COMPARISON.md. Разнообразие по разным углам, например: игровая HUD-эстетика
с крупной фактурой; уютный мягкий стиль (скругления 16+, пастель); ретро-будущее Y2K /
ремикс Win95; брутализм с жёсткой сеткой и чёрной типографикой; настольный клиент в духе
Steam/Discord с высокой плотностью; материальный дизайн с динамическим цветом. Тёмных ≥2,
светлых ≥1. Для каждого подбери диски осознанно (брутализм ≈ variance 8–10, Steam-клиент ≈
density 9) и отрази выбор в MASTER.md.

Запреты: реклама, оверлеи, агрессивные градиентные «космосы», эмодзи вместо иконок,
карикатурный пиксель-арт по всему интерфейсу (отсылки к игре — точечные и уместные).

## 6. Планка качества (проверяется по чек-листу, нарушение = переделка)

Доступность и база:
- Контраст текста к фону ≥ 4.5:1 (крупный текст ≥ 3:1); проверяй пары «текст/фон» из
  своих токенов, а не на глаз.
- Базовый размер текста 16px, межстрочный 1.5; ничего читаемого меньше 12px.
- Интерактивные цели ≥ 40×40px с отступами ≥ 8px; hover не несёт информацию в одиночку
  (дублируй состоянием/текстом).
- Фокус видим (focus-visible стиль у интерактива); иконки — только инлайн-SVG
  (lucide-стиль, stroke 2px), не эмодзи и не иконочные шрифты.

Токены и система:
- Все цвета/радиусы/тени/шрифты — CSS-переменные в `:root`, имена семантические
  (--bg, --surface, --text, --accent, --danger…), не «--blue-1». Совпадают с MASTER.md.
- Одна шкала отступов (кратна 4/8px), одна шкала радиусов, один набор длительностей
  анимаций с easing «выход быстрее входа» (например 150/250ms + cubic-bezier(0.2, 0, 0, 1)).
- Анимации в макете либо отсутствуют, либо осмысленны (подсказка пространства/статуса);
  укажи в MASTER.md, что из этого превратится в reduced-motion fallback.

Состояния (все три где-то в макете, статично):
- hover у карточки/кнопки, активный пункт навигации, скелетон загрузки; плюс один блок
  «пустое состояние» с CTA и один блок ошибки с кнопкой «Повторить» (можно на вторых
  экранах галереи как доп. секцию внизу макета).

Полнота:
- Макет выглядит как законченный продукт, а не вайрфрейм: реальные тексты, реальные
  числа, аккуратные пустоты. Русский язык, без «рыбы».
- 1440×900 основная, цельно при 1280×720; всё в пределах окна, без горизонтального
  скролла.
