# ЗАДАЧА: применить дизайн-систему «Сланец» к реальному UI лаунчера

Ты работаешь в репозитории `mc-launcher-v2` (Tauri 2 + React 19 + TypeScript + Tailwind 4, ядро на Rust). Ядро приложения ГОТОВО и протестировано (M0–M9 закрыты: запуск vanilla/Fabric/Forge/NeoForge, модпаки, MSA/офлайн-аккаунты, NSIS). Твоя задача — ТОЛЬКО фронтенд: перенести дизайн выбранного концепта «Сланец» из статического прототипа в реальный React-UI. Серверную часть (Rust, IPC-команды, состояния) НЕ ТРОГАТЬ.

## 0. Железные правила (нарушение = провал задачи)

1. **Темы меняют ТОЛЬКО палитру** — никогда layout, виджеты, структуру. Владелец 4 раза отклонял структурные эксперименты («ты просто цвет поменял» → «меню Minecraft» → «ужасно, ушло от UI которого я хотел»). Финальный вердикт: «Сланец» во всех темах, тема = CSS-переменные.
2. **Никакого фейка.** Каждый элемент UI обязан работать на реальных данных IPC. Нет данных для баннера/счётчика — не рисуй элемент. Пустые состояния — честные empty-state с CTA.
3. **Rust-ядро не трогать.** Единственное допустимое изменение вне `src/` — `src-tauri/tauri.conf.json` (см. фазу B, кастомный титлбар).
4. **Все новые строки — через i18n** (`src/i18n`, ключи ru + en). Никакого хардкода текстов в JSX.
5. **Никаких новых зависимостей.** Стек: react, zustand, lucide-react, tailwind 4. Иконки — lucide.
6. **Шрифты офлайн-безопасные.** НЕ подключать Google Fonts и любые сетевые ресурсы: лаунчер обязан выглядеть корректно без интернета. Используй системные стеки: UI — `"Segoe UI", system-ui, sans-serif`; mono — `"Cascadia Mono", "JetBrains Mono", Consolas, monospace`. Прототип использует Inter — системный Segoe UI приемлемая замена.
7. **Планка качества (обязательна):** контраст текста ≥ 4.5:1 в каждой теме; кликабельные цели ≥ 40×40px; видимый `:focus-visible`; состояния hover/активен/скелетон/пусто/ошибка у списков; `prefers-reduced-motion: reduce` отключает анимации; hover — не единственный носитель информации.
8. **Коммиты атомарные** с понятными сообщениями (стиль репо: `UI: …`). В UI-файлы секреты не попадают (их там и быть не может).

## 3. Фазы работ

### A. tokens.css + система тем
- Заменить палитру на «Сланец». ИМЕНА существующих переменных сохранить (весь Tailwind-маппинг продолжает работать), ДОБАВИТЬ недостающие: `--surface-2`, `--accent-soft`, `--border-strong`, `--on-accent`, `--ok`/`--danger` алиасы при необходимости.
- Темы через `data-theme` на `<html>` (не класс): `dark` (дефолт, можно без атрибута), `light`, `cb-dark`, `cb-light` (дальтоник: зелёный/красный → сине-оранжевая пара), `mc` («Глубинный сланец» — только палитра!). Палитры — из slate-pro.html.
- Новый модуль `src/theme/theme.ts`: применение темы (атрибут + `<meta name="color-scheme">`), хранение в localStorage, чтение `?theme=` из URL при старте (приоритет: query > localStorage > dark). API: `setTheme(id)`, `getTheme()`, `THEMES` (список с id, названием, группой, свотчами для карточек).
- Применять тему ДО первой отрисовки (синхронно в `main.tsx`), чтобы не мигало.

### B. Shell — каркас окна «как в прототипе»
- Кастомный титлбар 52px: бренд (квадрат-марка с иконкой куба + имя приложения из i18n), глобальный поиск, чип аккаунта (аватар-заглушка с первой буквой, имя, тип профика: «нелицензионный»/«MSA» — данные из state), кнопки окна (свернуть/развернуть/закрыть).
- Кастомный титлбар требует в `src-tauri/tauri.conf.json` `decorations: false`. Кнопки окна — `getCurrentWindow()` из `@tauri-apps/api/window` (`minimize()`, `toggleMaximize()`, `close()`), перетаскивание — атрибут `data-tauri-drag-region` на титлбаре (на кнопках его НЕ ставить). Проверь, что приёмки и ресайз окна не ломаются; если что-то идёт не так — откатись на нативную рамку и ОТРАЗИ это в отчёте.
- Сайдбар 216px: пункты с иконкой + подписью + счётчиком (Инстансы — реальное число из state). Активный пункт: мягкая подложка `accent-soft` + полоска 3px слева. Внизу фут: версия лаунчера (реальная, из `getVersion()` плагина app или константы сборки). Строку «Свободно: N ГБ» рисуй ТОЛЬКО если в ядре уже есть команда с этими данными; если нет — не рисуй.
- Поиск в титлбаре — РАБОЧИЙ, без фейка: фильтрует инстансы (и моды на странице модов) по подстроке, хоткей Ctrl+K ставит фокус, Esc чистит. Если считаешь правильнее отложить полноценный глобальный поиск — допустимо оставить только фильтр инстансов, но тогда подпись плейсхолдера честная («Поиск инстансов»).
- Баннер «Обновление лаунчера» из прототипа НЕ рисовать (нет реальных данных апдейта в этом месте UI).

### C. Страницы под паттерны «Сланца»
- **Инстансы (Главная + страница Инстансов):** карточки-плитки заменить на СТРОКИ как в прототипе: grid `44px 1fr auto auto` — плитка-иконка 44px (первая буква имени, `accent-soft`), имя + сабтайтл (лоадер/версия/статус запуска), версия моноширинным чипом (bg-цвет, border-strong), квадратная кнопка Play 40px (accent, on-accent). Действия (Оптимизировать/Папка/Дублировать/Удалить) — в выпадающем меню по кнопке-кебабу 40px ИЛИ вторым рядом при hover строки: выбери вариант, который проходит приёмки с клавиатуры (все действия достижимы с клавиатуры!). Статус запуска (загрузка N/M, подготовка, запущена) — инлайн в строке с aria-live; у запущенного вместо Play — квадратная Stop (danger).
- **Главная:** секции «Инстансы» (заголовок 18px + счётчик-чип + кнопка «Новый инстанс» ghost) и «Популярные модпаки» — только если на странице модов реально есть данные популярного списка; иначе Главная = только инстансы + пустое состояние с CTA.
- **Моды:** сохранить всю функциональность (поиск, установка из Modrinth, прогресс), переложить на паттерн строк прототипа (`.mod`: плитка 36px, имя, моно-версия, бейдж статуса, действия). Бейджи — мягкие: цвет текста success/danger на 14%-й подложке того же цвета с рамкой на 40%.
- **Настройки:** сохранить все реальные секции, стилистика — панели с заголовками-капсом 12–13px uppercase muted. Добавь раздел **«Темы»** (см. фазу D).
- **Onboarding и CreateInstanceDialog:** перекрасить токенами, выровнять кнопки по системе (primary/ghost, высота 44), структуру не ломать — там рабочая логика приёмок M4.
- Кнопки — единые классы (например `.btn-primary`/`.btn-ghost` в CSS): высота 44 (в таблицах 40), radius 8, primary = accent/on-accent, hover осветление через `color-mix`, ghost = рамка border-strong + hover surface-2.

## 4. Грабли, чтобы не наступить

- Tailwind 4: маппинг `@theme inline` уже настроен — новые переменные добавляй туда же, иначе утилиты `bg-*`/`text-*` не появятся.
- `data-tauri-drag-region` не должен покрывать кнопки — иначе клики окна перехватываются.
- При `decorations: false` окно теряет тень/ресайз-края на Windows — проверь ресайз и максимизацию; двойной клик по титлбару = maximize (реализуй).
- Не вставляй `?theme=`-парсинг после монтирования React (мигание) — синхронно до `createRoot`.
- Приёмочные скрипты могут ждать конкретные aria-label/тексты — не переименовывай i18n-ключи без нужды, меняй только классы/разметку.
- zustand-сторы и api/client.ts НЕ менять (только если для счётчиков/поиска нужны селекторы поверх — ок).
- lucide-react: иконки в строках 16–18px, в плитках 18–28px; stroke наследует currentColor.
